Kubernetes Reference

Quick access to kubectl commands, YAML templates, best practices, and troubleshooting guides.

kubectl Commands

Essential commands for managing Kubernetes clusters and resources.

Cluster Information

# Get cluster info
kubectl cluster-info
# Get nodes
kubectl get nodes
# Get all resources
kubectl get all

Pod Management

# Get pods
kubectl get pods
# Describe pod
kubectl describe pod <name>
# Execute in pod
kubectl exec -it <pod> -- /bin/bash

Deployments

# Get deployments
kubectl get deployments
# Scale deployment
kubectl scale deployment <name> --replicas=3
# Rolling update
kubectl set image deployment/<name> container=image:tag

Services

# Get services
kubectl get services
# Port forward
kubectl port-forward service/<name> 8080:80
# Expose deployment
kubectl expose deployment <name> --type=LoadBalancer

ConfigMaps

# Create from file
kubectl create configmap <name> --from-file=config.yaml
# Create from literals
kubectl create configmap <name> --from-literal=key=value
# Get configmap
kubectl get configmap <name> -o yaml

Troubleshooting

# Get pod logs
kubectl logs <pod>
# Follow logs
kubectl logs -f <pod>
# Events
kubectl get events --sort-by='.lastTimestamp'

YAML Templates

Common Kubernetes resource configuration templates.

Pod Template

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  labels:
    app: my-app
spec:
  containers:
  - name: my-container
    image: nginx:latest
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"

Deployment Template

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: nginx:latest
        ports:
        - containerPort: 80
        env:
        - name: ENVIRONMENT
          value: "production"

Service Template

apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
  type: ClusterIP

ConfigMap Template

apiVersion: v1
kind: ConfigMap
metadata:
  name: my-config
data:
  database_url: "postgresql://localhost:5432/mydb"
  debug_mode: "true"
  config.yaml: |
    server:
      port: 8080
      host: 0.0.0.0
    database:
      max_connections: 100

Best Practices

Recommended patterns and configurations for production Kubernetes deployments.

Resource Limits and Requests

Always specify resource requests and limits for your containers to ensure proper scheduling and resource management.

resources:
  requests:
    memory: "64Mi"
    cpu: "250m"
  limits:
    memory: "128Mi"
    cpu: "500m"

Health Checks

Implement liveness and readiness probes to ensure your applications are healthy and ready to serve traffic.

livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 30
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5

Labels and Selectors

Use consistent labeling strategies to organize and manage your resources effectively.

labels:
  app.kubernetes.io/name: my-app
  app.kubernetes.io/component: backend
  app.kubernetes.io/version: "1.0"
  environment: production

Security Context

Run containers with non-root users and restrict capabilities for enhanced security.

securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  allowPrivilegeEscalation: false
  capabilities:
    drop:
    - ALL

Troubleshooting

Common issues and their solutions for Kubernetes deployments.

Pod Stuck in Pending State

Check resource availability, node selectors, and taints that might prevent scheduling.

# Check pod events
kubectl describe pod <pod-name>
# Check node resources
kubectl top nodes

Service Not Accessible

Verify service selectors, endpoints, and network policies.

# Check service endpoints
kubectl get endpoints <service-name>
# Test service connectivity
kubectl run test --image=busybox --rm -it -- /bin/sh

CrashLoopBackOff

Check application logs, configuration, and resource limits.

# Check pod logs
kubectl logs <pod-name> --previous
# Execute into pod
kubectl exec -it <pod-name> -- /bin/sh
