## 🚀 How to Use

### First Time Setup (One-Time Only)

```bash
# 1. Initialize your Kubernetes cluster
./scripts/01-init-cluster.sh your_docker_username your_docker_pat_token

# Expected output:
# ✓ Namespace 'k8s-playground' is ready
# ✓ Service account created
# ✓ Kubernetes resources deployed
# ✓ Kubeconfig created: /tmp/kubeconfig-jenkins-1234567890.yaml
```

### Configure Jenkins Credentials

The script will guide you through adding two credentials to Jenkins:

**1. kubeconfig-credentials**
   - Type: Secret file
   - File: kubeconfig generated by the script
   - ID: `kubeconfig-credentials`

**2. docker-hub-creds**
   - Type: Username with password
   - Username: Your Docker Hub username
   - Password: Your Docker Hub PAT token
   - ID: `docker-hub-creds`

### Create Jenkins Pipeline Job

1. Go to Jenkins UI
2. Click "New Item"
3. Enter job name (e.g., "k8s-playground")
4. Select "Pipeline"
5. In "Pipeline" section:
   - Select "Pipeline script from SCM"
   - SCM: Git
   - Repository URL: `https://github.com/devopscl0ud/k8s-playground.git`
   - Credentials: (select if private)
   - Branch: `*/dev`
   - Script Path: `Jenkinsfile`
6. Save and test

### Configure GitHub Webhook (Optional but Recommended)

1. In repository Settings → Webhooks → Add webhook
2. Payload URL: `https://<JENKINS_URL>/github-webhook/`
3. Content type: `application/json`
4. Events: Just the push event
5. Save

# ✓ Namespace exists
# ✓ Service account configured

### Common Issues Quick Fixes

| Issue | Command |
|-------|---------|
| Deployment not created | `./scripts/01-init-cluster.sh` |
| Pods not starting | `kubectl -n k8s-playground logs -f k8s-playground-backend-xxx` |
| Image pull failing | `./scripts/02-troubleshoot-cicd.sh` |
| Service unreachable | `kubectl -n k8s-playground describe service k8s-playground-backend` |
| Need to restart pods | `kubectl -n k8s-playground rollout restart deployment/k8s-playground-backend` |

## 📊 Pipeline Stages Explained

Your Jenkinsfile now has these stages:

```
1. Checkout              → Git clone repo
2. Install & Test       → npm ci && npm test
3. Validate Prerequisites → Verify kubeconfig and registry credentials
4. Build & Push Image   → Docker build and push to registry
5. Deploy to Kubernetes → Create namespace, deployment, and update image
```

Each stage has detailed logging showing what's happening.

## ✅ Testing the Pipeline

### Manual Test

```bash
# Test that everything works without Jenkins
cd /workspaces/k8s-playground

# 1. Install dependencies
npm ci

# 2. Build Docker image
docker build -t docker.io/venky2222/k8s-playground-backend:test-image .

# 3. Push image (requires docker-hub-creds)
docker push docker.io/venky2222/k8s-playground-backend:test-image

# 4. Update deployment (this is what Jenkins does)
kubectl -n k8s-playground set image deployment/k8s-playground-backend \
  backend=docker.io/venky2222/k8s-playground-backend:test-image

# 5. Check rollout
kubectl -n k8s-playground rollout status deployment/k8s-playground-backend
```

### Jenkins Test

1. Open Jenkins UI
2. Go to your pipeline job
3. Click "Build Now"
4. Check "Console Output" for logs
5. If failed, use `./scripts/02-troubleshoot-cicd.sh` to debug

## 🔐 Security Notes

- Never commit kubeconfig to git (generated by script, not in repo)
- Never commit Docker credentials to git
- Use Jenkins credential storage for all secrets
- Service account has cluster-admin rights (development only - limit for production)
- Use separate namespaces for dev/staging/production in production environments
